# Sentra

Учебная система обнаружения фишинговых адресов и вредоносных Windows PE-файлов. В проект входят три URL-модели и файловый детектор. В отчёте видны оценка риска и наблюдаемые признаки. Для URL это домен, поддомен при его наличии и протокол. Для файлов — вариант формата PE, число секций и размер.

## Локальная демонстрация

В каталоге `sentra` выполните `python app.py` (в Linux используйте `python3`). Нужен Python 3.9 или новее. Откройте http://127.0.0.1:8765. Порт можно изменить переменной окружения `PORT`. В этом режиме вычисления выполняет процесс API, отчёты сохраняются в SQLite в `data/scans.db`. Для остановки нажмите Ctrl+C в терминале сервера.

## Стенд в Docker

Из того же каталога запустите `docker compose up --build -d`. Нужны работающий Docker Engine с Linux-контейнерами, Compose и свободный порт 8765. Стенд доступен по http://127.0.0.1:8765. При первом запуске Docker загружает образы и устанавливает Python-клиенты в образ приложения. Состояние сервисов показывает `docker compose ps`, журнал задач — `docker compose logs worker`, остановка — `docker compose down`.

При обновлении существующего стенда используйте `docker compose up --build -d --remove-orphans`, чтобы Compose убрал контейнеры исключённых сервисов.

API в одной транзакции записывает исходный статус в таблицу `scans` и задание с числовыми признаками в `scan_jobs`. Ответ с ID сразу возвращается браузеру. Фоновый поток API передаёт ID через RabbitMQ. Воркер Celery отмечает начало работы, выполняет классификацию и сохраняет итоговый отчёт в PostgreSQL. Redis возвращает готовый результат по ID в течение пяти минут, затем API читает отчёт из PostgreSQL. Таблицы находятся в томе `reports`.

После сбоя публикации диспетчер повторяет отправку. Незавершённое задание можно доставить повторно через пять минут. Повторная обработка сохраняет один конечный отчёт по ID. В локальном режиме тот же цикл работает с SQLite. Вкладка браузера запоминает ID текущей проверки и после обновления продолжает запрашивать её статус.

Команда `docker compose exec -T api python check_stack.py` создаёт одну проверку через REST. Скрипт сверяет полученный отчёт с записью PostgreSQL и результатом задачи в Redis по одному ID. По этому ID задачу можно найти в журнале воркера Celery.

## Обучение и оценка

В версии v2 URL получает среднее двух оценок. Случайный лес учитывает 23 структурных признака, а логистическая регрессия — наличие фрагментов длиной 3 и 4 символа. Словарь из 40 000 фрагментов определяется на обучающей части. Для PE обучен случайный лес по 18 полям заголовка, включая флаги COFF и выравнивание секций. В каждом лесу 40 деревьев. Для исполнения достаточно стандартной библиотеки Python.

**Данные.** В первой версии все 134 850 легитимных строк PhiUSIIL имели домен с префиксом www и пустой путь либо путь из одних слешей. Для обучения новой модели использована детерминированная подвыборка [GramBeddings](https://web.cs.hacettepe.edu.tr/~selman/grambeddings-dataset/) из [Train.csv в репозитории URLBERT](https://github.com/Davidup1/URLBERT/tree/master/dataset/grambedding). Исключены повторы адресов и конфликтующие метки. Поддомены одного регистрируемого домена отнесены к одной части по SHA-256 и встроенному списку публичных суффиксов tldextract. Для файлов сохранён исходный тест [ClaMP](https://github.com/urwithajit9/ClaMP/tree/master/dataset): объекты с совпадающими исходными 12 признаками остаются вместе.

**Пороги.** На валидации сравниваются лес и гибридная модель URL. Выбирается вариант с наибольшей полнотой при ограничении на долю ложных тревог. Для высокого риска бюджет на валидации — 1% для URL и 5% для PE, для среднего и высокого вместе — 4% и 12%. На других данных доли могут меняться. Границы среднего и высокого риска — 39 и 55 для URL, 17 и 41 для PE. Балл от 0 до 100 не калиброван как вероятность. Обучение / валидация / тест: 153 209 / 34 308 / 52 323 URL и 3 382 / 787 / 1 015 файлов.

| Выборка | Версия | TP | FP | FN | TN | Полнота | Доля ложных тревог среди легитимных |
|---|---|---:|---:|---:|---:|---:|---:|
| GramBeddings | v1 | 26 022 | 21 339 | 1 121 | 3 841 | 95,9% | 84,7% |
| GramBeddings | v2 | 24 535 | 856 | 2 608 | 24 324 | 90,4% | 3,4% |
| Ebbu2017 | v1 | 23 512 | 21 824 | 332 | 1 291 | 98,6% | 94,4% |
| Ebbu2017 | v2 | 18 999 | 815 | 4 845 | 22 300 | 79,7% | 3,5% |
| ClaMP | v1 | 456 | 38 | 72 | 449 | 86,4% | 7,8% |
| ClaMP | v2 | 518 | 36 | 10 | 451 | 98,1% | 7,4% |

Сравнение выполнено при рабочих порогах высокого риска обеих версий. [Ebbu2017](https://github.com/ebubekirbbr/pdd/tree/master/input) использован для внешней оценки. Из него удалены повторы, конфликтующие метки и домены обучения и валидации v2. Это исторический корпус, промежуточные результаты оценивались в ходе разработки. Совпадения с источниками v1 не исключались. Для оценки на текущем трафике нужен отдельный набор с более поздними датами сбора, включая легитимные страницы входа и обновлений. ClaMP также исторический, без отдельного теста на новых семействах ПО.

**Воспроизведение.** В отдельном окружении обучения установите scikit-learn==1.6.1 и tldextract==5.3.0. Из каталога sentra выполните:

```sh
python train.py Train.csv ClaMP_Raw-5184.csv candidate.json --external data_legitimate_36400.json data_phishing_37175.json
```

Аргумент `--baseline v1.json` добавляет сравнение с исходной моделью из Git-коммита 6a15e02 (файл sentra/models.json). SHA-256 входных данных: Train.csv — 9edc7314d2d3394792f63f5bc223a8c8ebd9c1d48ea451ed40c1bb496eb213b3, ClaMP_Raw-5184.csv — 3f63b88f9d9563394ece5c28bf90fffede46f241dac0d30e0228bb78febaff37.

### Эксперимент с адресами и сохранёнными страницами

Модель «Бренды в URL» отдельно считает вхождения 18 названий в регистрируемом домене, поддомене и пути. Она использует также структурные признаки и оценку по символьным фрагментам из v2. В эксперименте сравниваются три леса по 64 дерева с одинаковыми настройками. Третий лес дополнительно получает девять признаков форм и разметки из первых 65 536 символов сохранённой страницы. Скрипт исключает страницы размером свыше 1 МиБ. Для проверки ссылок на сайте достаточно ввести адрес.

Использованы первые два файла каждой официальной части train и test ревизии `eca603e`. Повторы URL и отпечатка анализируемого фрагмента исключены. Регистрируемые домены обучения, валидации и теста PhreshPhish разделены по сохранённому списку публичных суффиксов. Лексическая модель v2 была обучена отдельно на GramBeddings, поэтому эти ограничения не гарантируют полной независимости от её обучающих данных. Источник страниц — Thomas Dalton и соавторы, лицензия CC BY 4.0. [PhreshPhish](https://huggingface.co/datasets/phreshphish/phreshphish)

Для высокого риска каждой модели выбран порог с бюджетом 1% ложных тревог на валидации. В тесте 2 029 фишинговых и 2 228 легитимных страниц.

| Признаки модели | Обнаружено угроз | Полнота | Ложные тревоги | На 1 000 легитимных |
|---|---:|---:|---:|---:|
| Структура и фрагменты URL, лес на PhreshPhish | 981 | 48,3% | 65 | 29,2 |
| Те же признаки и расположение брендов | 1 024 | 50,5% | 58 | 26,0 |
| Те же признаки, бренды и HTML | 933 | 46,0% | 59 | 26,5 |

Обучение использует 4 608 страниц, валидация — 1 556. Пороги экспериментальной модели для среднего и высокого риска составляют 65,8 и 83,5. Матрицы ошибок, проверка на легитимных страницах с паролем и результаты переноса на другие наборы сохранены в `page_benchmark.json`.

На тех же 4 257 страницах при рабочих порогах v2 нашла 692 из 2 029 фишинговых страниц при 157 ложных тревогах, профиль с брендами — 1 024 при 58 ложных тревогах. На тестовых URL GramBeddings, прошедших фильтр доменов, полнота v2 составила 90,3%, у профиля с брендами — 40,4%. На Ebbu2017 полнота составила 79,6% и 17,9% соответственно. Среди 307 легитимных URL Ebbu2017 со словами входа или авторизации ложных тревог было 91 и 7. Эти различия между корпусами определили выбор v2 в качестве основной модели. В интерфейсе экспериментальный профиль включается в поле «Модель проверки».

Для воспроизведения в учебном окружении нужны также NumPy 2.0.2 и PyArrow 17.0.0. Команда запускается из каталога `sentra` с файлами из указанных источников.

```sh
python train_pages.py --train train-000.parquet train-001.parquet --test test-000.parquet test-001.parquet --gram Train.csv --ebbu data_legitimate_36400.json data_phishing_37175.json
```

### Сравнение файловых моделей

На 64 системных EXE и DLL с подтверждённой подписью Microsoft обе модели дали 0 предупреждений высокого риска при порогах Sentra 41 и EMBER 0,5. В `pe_benchmark.json` приведены контрольные суммы и обе оценки для каждого файла. Выборка представляет одного издателя.

Отдельно оценена детерминированная подвыборка официального архива `Dot_Net_test.zip`. На первых шести неделях (3 073 записи) установлены пороги с бюджетом 5% ложных тревог. В следующих шести неделях 1 480 вредоносных и 1 542 легитимных файла. EMBER обнаружила 1 468 угроз (99,2%) и дала 91 ложную тревогу (5,9%). Для Sentra диапазоны составили 747–798 (50,5–53,9%) и 60–76 (3,9–4,9%). Границы рассчитаны обходом обеих ветвей дерева, когда решение зависит от отсутствующих данных, включая выравнивание файла и младшие биты флагов DLL. Для EMBER использованы опубликованные признаки и веса. Выводы из этого теста относятся к .NET. [Данные и экстрактор EMBER2024](https://github.com/FutureComputing4AI/EMBER2024) · [Модель EMBER2024 PE](https://huggingface.co/joyce8/EMBER2024-benchmark-models)

Для воспроизведения установите в учебное окружение LightGBM 4.6.0, pefile 2024.8.26 и signify 0.7.1. Рядом с исходным `features.py` из `src/thrember` нужен `pefile_warnings.txt`. SHA-256 экстрактора и весов приведены в `pe_benchmark.json`. SHA-256 тестового ZIP — `b74c4181dbd77565fce16ba47c8ab0f7c7044ae6d880d859ec2c27365dea6299`.

```sh
python benchmark_pe.py --archive Dot_Net_test.zip --extractor features.py --model EMBER2024_PE.model --output pe_labeled_benchmark.json
```

### Смешанная URL-модель и проверка по времени

Профиль `mixed` объединяет лес по структуре адреса и расположению брендов с регрессией по символьным фрагментам. Обучение использовало 24 032 адреса GramBeddings, 8 846 Ebbu2017 и 6 780 PhreshPhish. Среди легитимных обучающих адресов признаки входа встретились у 1 622, оплаты — у 168, восстановления — у 186. Категории по ключевым словам могут пересекаться.

Пороги всех трёх моделей подобраны на 3 597 адресах за 9 сентября — 31 октября 2025 года при бюджете 10 ложных тревог на 1 000 легитимных адресов. Тест охватывает 1 ноября — 16 декабря 2025 года, 2 166 доменов, 2 278 фишинговых и 411 легитимных адресов. Из него исключены домены обучения и валидации. Пороги ниже приведены для этого сравнения. В приложении у ранее выпущенных моделей используются их исходные рабочие пороги.

| Модель | Порог | Обнаружено угроз | Полнота | Ложных тревог на 1 000 легитимных |
|---|---:|---:|---:|---:|
| Основная v2 | 89,7 | 308 | 13,5% | 7,3 |
| Бренды в URL | 89,1 | 346 | 15,2% | 2,4 |
| Смешанная | 72 | 706 | 31,0% | 4,9 |

У смешанной модели две ложные тревоги. В тесте всего 20 легитимных URL с признаками входа, 9 с признаками восстановления и ни одного с признаками оплаты. Оценивать надёжность на платёжных страницах по этому тесту пока нельзя. Отдельный профиль доступен в форме проверки. Матрицы ошибок всех моделей находятся в `mixed_benchmark.json`.

Команда воспроизведения использует файлы PhreshPhish ревизии `eca603e` и зависимости, перечисленные выше.

```sh
python train_mixed.py --gram Train.csv --ebbu data_legitimate_36400.json data_phishing_37175.json --train train-000.parquet train-001.parquet --validation test-000.parquet test-001.parquet --test test-002.parquet test-003.parquet test-004.parquet test-005.parquet test-006.parquet
```

### Win32, Win64 и стоимость проверки

На официальных архивах EMBER2024 отобраны записи с первым байтом SHA-256 меньше 2. Порог каждой модели для каждой архитектуры подобран на первых шести неделях при бюджете 5% ложных тревог. Следующие шесть недель отложены для теста. Диапазоны Sentra учитывают недостающие поля заголовков тем же способом, что и в эксперименте .NET.

| Набор | Угроз / легитимных | Sentra, обнаружено / ложных тревог | EMBER, обнаружено / ложных тревог |
|---|---:|---:|---:|
| Win32 | 825 / 1 030 | 405–433 / 37–54 | 813 / 76 |
| Win64 | 243 / 514 | 19–22 / 10–17 | 243 / 33 |

В замере времени и памяти участвовали 16 подписанных Microsoft файлов, по 8 каждого формата, размером от 15 360 до 2 050 600 байт. Для каждой пары «модель и файл» запускался отдельный процесс Windows. Измерялось время от чтения байтов до получения оценки после загрузки модели. Пиковая резидентная память учитывает весь процесс, включая загрузку библиотек. Медианы Sentra — 0,21 мс и 35 МиБ, EMBER — 83 мс и 137 МиБ. Полные замеры приведены в `pe_cost.json`.

EMBER подходит для углублённого исследовательского сравнения. При выбранных порогах на отложенных Win32 и Win64 она ошибочно отметила 7,4% и 6,4% легитимных файлов соответственно. Для веб-сканера принят лёгкий детектор, а выбор рабочего порога EMBER требует отдельной проверки на легитимном ПО разных издателей.

Для углублённой проверки одного локального файла до 10 МиБ используйте режим `--file` в исследовательском окружении. Итоговый JSON содержит SHA-256, оценку Sentra, оценку EMBER и сравнение с порогом соответствующей группы (.NET, Win32 или Win64). Анализ читает байты файла без его запуска.

```sh
python benchmark_pe.py --archive Win32_test.zip --sample-bytes 2 --extractor features.py --model EMBER2024_PE.model --output win32_benchmark.json
python benchmark_pe.py --archive Win64_test.zip --sample-bytes 2 --extractor features.py --model EMBER2024_PE.model --output win64_benchmark.json
python profile_pe.py --manifest verified_paths.txt --extractor features.py --model EMBER2024_PE.model --output pe_cost.json
python benchmark_pe.py --file example.exe --extractor features.py --model EMBER2024_PE.model --output file_report.json
```

## REST API

| Метод | Маршрут | Данные |
|---|---|---|
| POST | /api/scans/url | JSON с полем `url` и необязательным `profile`. Доступны `default`, `brand` и `mixed` |
| POST | /api/scans/file | application/octet-stream, до 10 МиБ, необязательный заголовок X-File-Name с именем в percent-encoding |
| GET | /api/scans | До 100 последних отчётов |
| GET | /api/scans/{id} | Текущий статус, наблюдения и результат после завершения |
| GET | /api/models | Размеры выборок и матрицы ошибок |
| GET | /api/benchmarks | Сопоставимые результаты отложенных URL- и PE-тестов, время и память |

После приёма POST возвращает HTTP 202, статус `queued`, ID и заголовок `Location` с адресом проверки. По этому адресу доступны статусы `queued`, `running`, `done` и `failed`. Готовый отчёт содержит версию модели, оценку и признаки. Старые завершённые отчёты читаются со статусом `done`. HTTP 400 означает ошибку входных данных, 404 — неизвестный ID, 413 — превышение размера, 415 — неподдерживаемый тип запроса, 503 — недоступность сервиса.

Запустите `python -m unittest test_api` из каталога проекта для проверки приёма URL и PE, сохранения отчётов и отклонения некорректных данных. Тесты используют временную базу.
