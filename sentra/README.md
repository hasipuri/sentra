# Sentra

Учебная система обнаружения фишинговых адресов и вредоносных Windows PE-файлов. Две обученные модели входят в проект. Интерфейс показывает оценку от 0 до 100, признаки объекта, последние 100 отчётов и результаты тестирования моделей.

## Локальная демонстрация

В каталоге `sentra` выполните `python app.py` (в Linux используйте `python3`). Нужен Python 3.9 или новее. Откройте http://127.0.0.1:8765. Порт можно изменить переменной окружения `PORT`. В этом режиме вычисления выполняет процесс API, отчёты сохраняются в SQLite в `data/scans.db`. Для остановки нажмите Ctrl+C в терминале сервера.

## Стенд в Docker

Из того же каталога запустите `docker compose up --build -d`. Нужны работающий Docker Engine с Linux-контейнерами, Compose и свободный порт 8765. Стенд доступен по http://127.0.0.1:8765. При первом запуске Docker загружает образы и устанавливает Python-клиенты в образ приложения. Состояние сервисов показывает `docker compose ps`, журнал задач — `docker compose logs worker`, остановка — `docker compose down`.

Python REST API извлекает признаки, передаёт их в RabbitMQ и ждёт результат задачи Celery через Redis. Воркер выполняет классификацию. API сохраняет отчёт в PostgreSQL и ставит в очередь задачу публикации события в Kafka. Тема `sentra.scan.completed` содержит идентификатор проверки, тип объекта и уровень риска. Для наблюдения за событиями используйте:

```sh
docker compose exec kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server kafka:9092 --topic sentra.scan.completed --from-beginning
```

Журнал PostgreSQL хранится в именованном томе. Доставка событий Kafka допускает пропуски при сбое между записью отчёта и постановкой задачи, а при повторной доставке события можно сопоставить по ID. Веб-сервис предназначен для локального однопользовательского стенда.

## Обучение и оценка

В каждой модели 17 деревьев глубиной до 7 с выборкой объектов с возвращением и случайным подбором признаков и порогов. Итоговая оценка — средняя доля вредоносных примеров в достигнутых листьях со сглаживанием. Это учебная шкала риска. Пороги уровней — 35 и 65. Тестовая положительная классификация соответствует высокому риску.

* Для модели URL использованы 10 структурных признаков адреса. Повторы одинаковых URL удалены. Разбиение на обучение и тест выполнено по имени хоста, поэтому один хост принадлежит только одной части. Поддомены одного сайта могут попасть в разные части. Данные — Arvind Prasad и Shalini Chandra, [PhiUSIIL, UCI, CC BY 4.0](https://archive.ics.uci.edu/dataset/967/phiusiil+phishing+url+dataset).
* Для модели файлов использованы 12 полей заголовков PE. Объекты с одинаковым вектором признаков отнесены к одной части. Источник — [ClaMP, таблица ClaMP_Raw-5184.csv](https://github.com/urwithajit9/ClaMP/tree/master/dataset). Набор содержит исторические образцы, поэтому показатели нельзя переносить на современное ПО без дополнительной проверки.

| Объект | Обучение | Тест | Обнаружено угроз | Пропущено | Ложные тревоги | Верно отклонено |
|---|---:|---:|---:|---:|---:|---:|
| URL | 189256 | 46110 | 10407 | 8719 | 344 | 26640 |
| PE | 4169 | 1015 | 456 | 72 | 38 | 449 |

Обучение воспроизводится командой `python train.py путь/к/phiusiil.zip путь/к/ClaMP_Raw-5184.csv`. Скрипт читает таблицы признаков и перезаписывает `models.json`. Проверка сайта выполняется по структуре URL, без сетевых запросов. Проверка файла ограничена заголовками PE. Исходный файл обрабатывается в памяти, в отчёте сохраняются имя и признаки.

## REST API

| Метод | Маршрут | Данные |
|---|---|---|
| POST | /api/scans/url | JSON с полем url |
| POST | /api/scans/file | application/octet-stream, до 10 МиБ, необязательный заголовок X-File-Name с именем в percent-encoding |
| GET | /api/scans | До 100 последних отчётов |
| GET | /api/models | Размеры выборок и матрицы ошибок |

Успешная проверка возвращает HTTP 201 и отчёт с ID, типом объекта, временем UTC, признаками и оценкой. HTTP 400 означает ошибку входных данных, 413 — превышение размера, 415 — неподдерживаемый тип запроса, 503 — недоступность сервиса.

Запустите `python -m unittest test_api` из каталога проекта для проверки приёма URL и PE, сохранения отчётов и отклонения некорректных данных. Тесты используют временную базу.
